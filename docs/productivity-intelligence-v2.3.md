# Masum-Chronos v2.3 — Galaxy Productivity Intelligence

## What ships

v2.3 adds a collapsible **Galaxy Intelligence** module inside the To-Do Mission Control workspace.

- **Activity Heatmap:** 84-day, seven-rows-by-twelve-weeks history. Daily activity = completed Focus sessions + completed missions retained in local snapshot.
- **Focus Trend:** seven or thirty daily bars, each representing recorded minutes from completed focus sessions.
- **Performance Metrics:** recorded focus duration, completed Focus sessions, completed missions, and active days in the chosen 7/30-day window.
- **Estimated vs Recorded Focus:** compares each mission's expected minutes with recorded focus minutes. The app now attaches the duration of a *fully completed focus Pomodoro* to the selected mission, as `focusSeconds` in the existing mission payload. No new SQL tables or third-party analytics platform.
- **CSV report:** UTF-8, Excel-friendly 84-day daily report and retained mission snapshot including estimates and known focus. User-generated names with spreadsheet formula prefixes are escaped to prevent spreadsheet formula injection.
- **Print / Save PDF:** uses the user's browser's native Print dialog with dedicated print CSS, from which **Save as PDF** can be selected. This is not an automatically generated PDF download or third-party conversion. Webview users should open the PWA in a browser for file export.
- **Futuristic styling:** current themes retained; accessible heatmap buttons and summary details limit default screen clutter.

## Definitions and accuracy

A `completed Focus session` is a focus timer that counted down to zero. Actual time is its configured full session duration and is credited once upon successful completion. Partial/paused sessions, stopwatch, countdown mode and break sessions **do not** accrue mission focus time. Previous app versions did not record mission-level focus association: legacy tasks therefore show **Not tracked**, never a misleading "zero minutes actual" comparison.

Calendar dates are evaluated in the device-local timezone. Completion counts are derived from the *retained* task history. Deleted tasks, cleared completed tasks, and tasks that have not been synced to this device cannot be recovered from this report. `stats.daily` continues to hold previously recorded focus counts. The report is analytical, not an external billing-grade time-tracking service.

Tasks newly generated by daily/weekly/monthly recurrence get `focusSeconds: 0` and do not inherit previous occurrence attribution. The field is sanitized and preserved by the browser state, Supabase JSONB mission payload and authenticated VS Code local sync bridge.

## User acceptance testing

1. Open Chronos and go to **To-Do → Galaxy Intelligence**. Expand the card and switch between Last 7 Days and Last 30 Days.
2. Run a complete 1-minute Focus session on an explicitly selected mission. Confirm that mission appears under Estimated vs Recorded Focus and totals increment exactly once. Ensure countdown/break/stopwatch do not increment mission actual focus.
3. Complete a normal task, inspect its heatmap day, and confirm Done count increases. Task with no Focus history should not be labeled as an actual 0-minute project.
4. On a mobile device, test the 84-day heatmap layout, trend bars, details/summary keyboard interaction and responsive KPI cards.
5. Click **Export CSV**, open the report in a local spreadsheet, and verify date, session, completion and mission rows. Check formula-like mission names stay inert.
6. Click **Print / Save PDF** in a browser. Verify the browser print dialog opens and offers Save as PDF. The report itself should print without the full application dashboard or timers.
7. Verify Settings tabs, Smart Calendar, recurring missions, dependency network, Sound Studio and Local Link still work.
8. If Cloud Sync is enabled, test account sign-in, two-browser merge and mission focus attribution. VS Code should receive the same `focusSeconds` during local sync without wiping existing fields.
9. Confirm previous versions (v2.2.0-beta.1 and older) migrate without clearing local missions or unrelated settings.
10. CI: `npm run lint`, `npm run test:intelligence`, `npm run test:calendar`, all prior regressions, VSIX packaging and GitHub Pages deployment must pass.

## Limits

- Historical mission focus cannot be reconstructed for sessions recorded before this release.
- CSV/PDF export is intentionally **browser/PWA-only**. PDF output uses browser printing, not a direct binary PDF generator.
- Reporting for a different timezone is not supported in v2.3; device-local time is used.
- No cross-project analytics sync or NovaStudy dashboard integration has been implemented yet. Reusing this pure analytics module in NovaStudy is a possible later phase.
- Browser device print rendering and real signed-in multi-device synchronization require manual acceptance tests; CI cannot prove them.
